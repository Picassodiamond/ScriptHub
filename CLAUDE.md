# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ScriptHub: a standalone Django 5 app (Python 3.10+, only dependency is Django) that discovers, configures, runs and monitors Python/Bash/batch scripts from a browser. It runs on Windows and executes scripts locally or on remote Linux hosts over the system `ssh`. There is **no database, Redis, Celery or Node**: everything is JSON/text files. It also runs as a desktop app (`desktop.pyw` / `manage.py desktop`, see below). There is **no authentication** by design (single trusted user, localhost); creating and editing scripts in the browser is therefore arbitrary code execution, so treat it with care. (The old Ad-hoc screen was removed; History still shows the code of old ad-hoc runs.) `README.md` is the full user/ops reference.

## Commands

```bash
python manage.py runserver --noreload     # run; --noreload matters: run threads live in the web process and reloads kill jobs
python manage.py desktop                  # desktop app (own window, tray); or double-click desktop.pyw
python manage.py test runner              # all tests (~200, a few skipped on Windows)
python manage.py test runner.test_editor                            # one module
python manage.py test runner.test_editor.SomeClass.test_name        # one test
node tools/test_highlight.js              # tests for static/js/highlight.js
```

No linter/build step. Env vars: `SCRIPTHUB_DEBUG` (default `1`), `SCRIPTHUB_ALLOWED_HOSTS`. The test suite must leave real `runtime/executions` and `runtime/presets` untouched (patch `config.EXECUTIONS_DIR`, `config.PRESETS_DIR` and `config.BACKUPS_DIR` in any test that starts a run, saves values or saves a script (`runtime/script_ids.json` sits next to `CONFIG_FILE`); posting the run form starts a run) and must not modify the bundled `scripts/`; check this after adding such tests.

## Architecture

- `config.py` + `runtime/config.json`: validated settings (`runner/validators.py`), atomic writes with `.bak`. Settings → Features toggle `enable_script_editing` (also gates New script); views must honour it (return 403 page, not just hide links). A legacy `enable_adhoc` key is dropped by the validator.
- **Open folder** (`runner/workspace.py`, `folder_views.py`, page `/folder/`): one script folder is open at a time; it is UI state in `runtime/workspace.json` (`folder`, `recent` max 10, `favorites`), next to `config.CONFIG_FILE` so tests that patch that are isolated. Not a setting: Settings has no folder section. A legacy `script_directories` in config.json seeds the state until the first change. Script files can be opened next to (or without) the folder: workspace state `files` (max 30; `open_folder(file)` adds, `close_file` / `close_all_files`; a file stored as `folder` by 2.1 betas is read as a file); `roots()` = folder + files outside it; discovery scans a file root on its own (root = its parent); `current_is_file()` = files but no folder (New script refused); POST `folder/open/` takes several `path`s, `folder/close-file/` (`path` or `all=1`); `desktop.ask_file` returns a list (askopenfilenames). Script tabs (designer.js): open script ids in localStorage `scripthub.openScripts.<data-ws>` (`data-ws` on `.doc` = folder path or `files`), rendered from the `wb-palette` JSON around the current script's file tab; switching keeps the right-hand tab (`pageFor`), explorer clicks on script pages too. Menu bar `templates/_menubar.html` (File: new/open file/open folder/recent/favourite/close/settings, View, Run, Help; `details[data-menu]`, hover switches in app.js, items keep hotkeys via `usable()`); explorer header = folder title + New script/Rescan/Collapse; palette lists folders (`wb-folders`), in-page folder browser (`workspace.browse`) plus the native dialog in desktop mode (`data-pick-submit`). New script creates files in the open folder.
- **Discovery** (`runner/discovery.py`): scans the open folder (`workspace.roots()`) at most `MAX_DEPTH` (3) sub-folder levels deep, skipping `.`/`$` folders (New script enforces the same limit). Scanning runs in a background thread (`_Job`, progress via `status()` / `GET folder/scan/`, shown in the status bar); `scan()` waits at most `AUTO_WAIT` early in a scan, then returns the last or partial results; views use `rescan()` (bounded wait) and `update_file(path)` after editing one script, never `scan(force=True)` (that blocks; tests only). The native folder dialog (`desktop.can_pick_folder`) works in desktop mode and for loopback requests; "Open folder…" links carry `data-open-folder` and open it directly, the `/folder/` page is the fallback; script id = the stable `"id"` from the metadata block when present (`runner/ids.py`: 12 random hex, written by the first `metadata.save_raw`; `Script.path_id` = sha1 of the normcased path[:12] otherwise); old ids are aliases in `script_ids.json` (`ids.canonical`, `ids.adopt` moves presets/backups dirs), `discovery.get_script` accepts an id, path id or alias, history canonicalises run `script_id`s (`history.canonical_script`); duplicate stable ids: `_place` keeps the original (alias home, else created first), the copy gets `id_conflict` and its path id until its next save (`save_raw(conflict=True)`). Each script has a JSON metadata sidecar next to it (fallback `runtime/metadata_overrides/<id>.json`), validated by `parameter_service.validate_metadata`. Symlinks escaping the root are skipped. Views never accept file paths from the browser, only script ids.
- **Overview = configuration**: `script_detail` (GET form, POST saves metadata) holds what used to be Configure; `script_configure` only redirects GETs there (POSTs are handled the same). Metadata keys `enabled`, `timeout`, `allow_concurrent` were removed: `parameter_service.REMOVED_KEYS` are dropped by `validate_metadata`; every valid script is runnable. The script id is used in URLs only, never shown.
- **Parameters** (`runner/parameter_service.py`): type registry, validation, and `build_arguments` (flag / positional / env). This is the single place that turns form values into argv.
- **Execution** (`runner/executor.py`, `runner/process_manager.py`): `ExecutionSpec` -> `build_command` -> `ExecutionManager` (singleton `manager`; in-memory queue + threads, global/per-host limits and one run per script at a time (no per-script options), the Settings default timeout, and cancel with process-tree kill). Never use a shell: argument lists locally; for SSH the remote command is built with `shlex.quote` and `REMOTE_WRAPPER` (prints `__SR_PID__<pid>`, `cd`, `exec env`). The script file on Windows is streamed over stdin to the remote interpreter. Batch args reject cmd metacharacters; PATH/LD_PRELOAD-style env vars are forbidden from parameters.
- **Line tracing** (`runner/tracing.py`): optional per run (`ExecutionSpec.trace`), Python/Bash only. Markers `\0SRL<n>\0` are written to stderr by a Python launcher (`PY_LAUNCHER`) or a bash DEBUG trap, stripped by `MarkerFilter` in `executor.pump`, and stored in the run folder (`trace.log`, `trace.last`, `trace_source`). Stopping is one-way: stop file locally, `kill -USR1 <remote_pid>` over SSH.
- **Step debugger** (`runner/tracing.py` `PY_DEBUG_LAUNCHER` / bash DEBUG trap on fd 9; `ExecutionSpec.debug`, implies trace): control channel is the process stdin kept open (local and SSH), line commands `step|continue|pause|detach|bp 1,2`. Debuggee pauses on entry and reports via stderr markers `\0SRP<line>\0`, `\0SRR\0`, `\0SRV<json>\0` (filtered by `MarkerFilter`). Manager holds state in memory: `debug_command()` / `debug_state()`; endpoint `POST executions/<id>/debug/`; status JSON has `debug`. Run mode form field is `mode` = normal|trace|debug (legacy `trace=1` still accepted). Tests: `runner/test_debugger.py`.
- **History** (`runner/history.py`, `history_ops.py`): `runtime/executions/RUN-YYYYMMDD-NNN/{metadata.json,stdout.log,stderr.log}`. Retention: history days delete runs, log days delete only logs. On startup `apps.py` marks runs whose `owner_pid` is dead as Interrupted. Processes are not recovered across restarts (by design).
- **Saved parameters** (`runner/presets.py`): YAML files in `runtime/presets/<script id>/` — `<slug>.yaml` per preset, `recent/<run id>.yaml` per recent run (last 10 distinct, recorded in `script_start`; newest by `saved_at` then file mtime), written/read by `runner/yamlish.py` (a small YAML subset, no dependency). Older layouts (`<stem>.params.json` next to the script, `runtime/presets/<id>.json`, v1 `<id>/<slug>.json`) migrate on load and are removed. Functions take the Script object (id + path); each operation touches only its own file; an unreadable file is skipped and never overwritten. Never store passwords or non-editable params; re-validated against current metadata on load. Run view: `?preset=<slug>|@<n>|-` (empty = last run), `?tab=params` opens the comparison grid (`presets.grid`), shown in the collapsible bottom panel `#saved-panel` under the script (`_script_doc.html`; `html.bottom-on`, localStorage `sr.bottom` / `sr.bottomH`, Ctrl+J, drag the top edge).
- **Editor / New script** (`runner/script_editor.py`, `edit_views.py`, `new_views.py`): saves are atomic with hash-based conflict detection; the previous version goes to `runtime/backups/<id>/` (`runner/backups.py`: timestamped copies, last 10, `versions`/`read`, old `<script>.bak` migrated by `migrate_side_bak` and only deleted after the copy reads back identical); Restore previous / Versions… (`_restore.html`, POST `previous` or `version`); newline policy `.bat` CRLF, `.sh` LF. New script (`/scripts/new/`, `+` in the explorer header with `?from=<script id>` to prefill its folder) writes a starter + metadata sidecar with `"xb"` (never overwrites), rejects absolute/drive/`..` sub-folders, then redirects to `script_run`. Web tests start runs with `WebCase.start_script()` (`runner/test_editor.py`).
- **Views** are split by area (`views.py`, `script_views.py`, `execution_views.py`, `history_views.py`, `preset_views.py`, `edit_views.py`, `new_views.py`, `folder_views.py`); routes in `runner/urls.py`. Run is one step: the run form posts to `script_start` (validate, start; `from_preset=<slug>|@<n>` runs saved values; errors re-render run.html), which redirects to `script_run?open=<run id>`: the run opens as a centre tab (`designer.js` run tabs, iframe of `execution_console?embed=1` = `base_embed.html`). There is no Review step. Jobs is merged into History (`executions/` redirects; `?partial=1` = the Running panel History polls), with a submit token to stop double submits. Every run records the client address as `initiator`.
- **Desktop mode** (`runner/desktop_app.py`, `desktop_tray.py`, `desktop.py`; no extra packages): launcher runs Django in-process with `django.core.servers.basehttp.ThreadedWSGIServer` + `StaticFilesHandler` on 127.0.0.1:random, sets `SCRIPTHUB_DESKTOP_TOKEN`; `DesktopTokenMiddleware` then 403s every request without the token cookie (set from `?desktop_token=`). Window = Edge/Chrome `--app` with `runtime/desktop-profile`; window presence from page heartbeats (`/desktop/ping/`, `/desktop/bye/` in app.js). Tray + notifications via ctypes `Shell_NotifyIconW` (Windows only). Reveal via explorer (by script/run id) is desktop-only (404 in server mode, buttons only when `desktop`). The folder picker via tkinter also answers loopback requests in server mode (`folder_picker` context flag; 404 for remote clients); tests must mock `desktop.ask_directory`, since the test client is 127.0.0.1. Single instance via `runtime/desktop.json`. Start with Windows = `.cmd` in the Startup folder.
- **Frontend (v2 workbench)**: one stylesheet `static/css/workbench.css` (dark default + `[data-theme=light]` tokens; theme/side-panel state in localStorage, applied by an inline head script), vanilla JS, SVG icon sprite inline in `templates/base.html`. No page header (no crumbs/title/actions blocks; the console has its own top bar, Review/Run their bottom `side-bar`). Shell = menu bar (top) / activity bar (Home, Library, Runs … Settings) | side panel (`{% block side %}`, default `_explorer.html`; Jobs/console use `_runs_side.html`, History its filters, Settings a section nav) | main (crumbs/heading/actions/tabs blocks) | status bar. Script pages extend `runner/_script_base.html` (tab strip `_script_tabs.html`; active tab from `url_name`). Lazy shared context in `runner/context.py` (`wb_tree`, `wb_runs`, `wb_palette`). `static/js/app.js`: flashes, `data-confirm`, `data-once` (uses `form.elements`, so buttons outside the form with `form=` work), `data-hotkey` shortcuts (`r`, `g l` chords, `Ctrl+Enter`, `F10|n`), Ctrl+K palette, `?` sheet. Script pages share the `.split` grid (centre + right column). The centre is identical on Overview / Run (`_script_doc.html`, fed by `script_views.doc_context()`): script (editor when editing is on; saves POST to `script_edit` via fetch so the right column survives), metadata JSON (raw form to `script_configure_raw`, `back` = page to return to) and the `.params.json` grid. The Overview / Parameters (`script_parameters`: definitions + saved values) / Run tabs head the right column (collapsible: `html.side2-off`, localStorage `sr.side2`, Ctrl+Alt+B) (those pages empty `{% block tabs %}`), so switching only changes that column; designer.js keeps the picked centre tab in sessionStorage. Run = `script_run` (run form); `script_edit`/`script_source` URLs remain for full-screen, errors/conflicts and downloads; save/restore redirect to `script_run` when runnable. Review (`run_confirm`) keeps the read-only `_designer_doc.html`. `static/js/designer.js` does tabs, parameter-to-line marking and save-in-place. Own syntax highlighter (`static/js/highlight.js`), editor overlay (`static/js/editor.js`).
- **Metadata** (`runner/metadata.py`): a JSON comment block in the script (`# --- scripthub ---` … `# --- end scripthub ---`, `::` for .bat/.cmd); `save_raw` rewrites only the block (keeps newline/BOM, backs up the previous version in runtime/backups/, writes the stable id), removes an old `<stem>.json` sidecar (still read when there is no block) and falls back to `runtime/metadata_overrides/` if the script is not writable. No raw-JSON tab: the block is edited in the script editor; designer.js refuses saving an edited block together with the Overview/Parameters form.
- `scripts/` holds the bundled example scripts (metadata block at the top of each); `runner/test_bundled_scripts.py` exercises them against stubs.

## Gotchas

- Windows file replace can raise `PermissionError`; use `runner/fsutil.py` (atomic write/read with retry) instead of raw `os.replace`/`open` for JSON state.
- In tests, write script fixtures with `write_bytes` (not `write_text`) to avoid CRLF conversion; use a unique submit token per start, since the manager remembers tokens.
- SSH is tested only against a fake `ssh` via the `ssh_executable` setting, not a real host.
- Do not commit the untracked `IdeasForFuture.tx` in the repo root.
- **One Save per script page** (`designer.js` `saveAll`, button `[data-save-all]` in `_script_doc.html`): saves the dirty parts in order — script in place (fetch to `script_edit`), then metadata from the JSON tab (`script_configure_raw`) or the forms (`#configure-form` -> `script_detail`, `#params-form` -> `script_parameters`, the parameter editor exposes `form.srSerialize`); JSON tab + form both dirty is refused; a failed part falls back to a native submit so the server shows its errors; metadata saves reload the page (`sessionStorage sr.saved` -> "Saved." flash).
